Configuración · Una sola vez

Cómo activar el backend del taller

Backend basado en Supabase — Postgres administrado, gratis, muy confiable. Sigue estos pasos desde un desktop (necesitarás un editor de texto). Tarda ~10 minutos y solo se hace una vez.

1

Crear cuenta y proyecto en Supabase

Ve a supabase.com y entra con tu correo o cuenta de GitHub. El plan gratuito incluye 500MB de base de datos y 50,000 usuarios mensuales — más que suficiente.

Presiona "New project". Asigna:

• Name: taller-innovacion (o lo que prefieras)

• Database password: genera uno fuerte y guárdalo (no lo necesitarás para este taller, pero Supabase lo pide)

• Region: la más cercana a ti (ej. East US (North Virginia) para Latinoamérica)

Presiona "Create new project" y espera ~2 minutos a que termine de provisionar.

2

Crear la tabla y políticas con SQL

En el menú lateral izquierdo, abre el SQL Editor (ícono de consola).

Presiona "New query", pega este bloque completo, y luego presiona "Run":

create table participants (
  id text primary key,
  timestamp timestamptz not null,
  name text not null,
  area text not null,
  years text,
  scores jsonb not null,
  gaps jsonb
);

alter table participants enable row level security;

create policy "anon insert" on participants
  for insert to anon with check (true);

create policy "anon select" on participants
  for select to anon using (true);

create or replace function reset_participants(p_password text)
returns void
language plpgsql
security definer
set search_path = public
as $$
begin
  if p_password != 'CAMBIA_ESTE_PASSWORD' then
    raise exception 'password incorrecto';
  end if;
  delete from participants;
end;
$$;

grant execute on function reset_participants(text) to anon;

Importante: antes de presionar Run, cambia CAMBIA_ESTE_PASSWORD por el password que vas a usar para el botón "Reset Datos" en admin. Este password queda guardado en la base de datos, NO en el HTML.

Si todo sale bien verás "Success. No rows returned".

3

Copiar URL y Anon Key del proyecto

En el menú lateral, ve a Project Settings → API (ícono de engrane).

Copia los dos valores que verás:

• Project URL: algo como https://abcdefgh.supabase.co

• anon / public key: una cadena larga que empieza con eyJ...

No copies la service_role key — esa es secreta y nunca debe ir en el HTML. La anon key sí está diseñada para ser pública.

4

Pegar las credenciales en los archivos

Abre participante.html y admin.html en un editor de texto (VS Code, Notepad, TextEdit, etc.).

En ambos archivos, busca y reemplaza:

• SUPABASE_URL_PLACEHOLDER → tu Project URL del paso 3

• SUPABASE_ANON_KEY_PLACEHOLDER → tu anon key del paso 3

Guarda los archivos. El password de admin no va aquí — ya quedó en la base de datos (paso 2).

5

Subir los archivos a GitHub Pages

Ve a github.com y crea una cuenta si no tienes. Crea un repositorio nuevo (botón "New" o "+"). Nómbralo por ejemplo taller-innovacion. Márcalo como Public (GitHub Pages gratuito requiere repositorio público).

Sube los 4 archivos (index.html, participante.html, admin.html, INSTRUCCIONES.html) arrastrándolos al repositorio.

Ve a Settings → Pages, en "Branch" selecciona main y guarda. En 1-2 minutos tu sitio estará en https://TU_USUARIO.github.io/taller-innovacion.

6

Compartir con los participantes

Comparte la URL directa a participante.html con todos los participantes por WhatsApp, email o QR. Ellos solo necesitan abrir el link — no instalan nada.

Tú abre admin.html en tu pantalla y presiona "Actualizar" para ver las respuestas en tiempo real.

Sobre seguridad: La anon key de Supabase está diseñada para ser embebida en código del lado del cliente. Las políticas de Row Level Security (RLS) configuradas en el paso 2 garantizan que con esa key solo se puede insertar y leer respuestas — no se pueden borrar ni modificar registros existentes. El password de admin vive en la función de Postgres, no en el HTML, así que aunque alguien lea el código fuente no puede borrar datos.
¿Por qué Supabase? Es Postgres administrado con uptime de nivel empresarial. A diferencia de servicios chicos de JSON, no se cae a media sesión. Cada respuesta es un INSERT atómico (no hay race condition cuando varios participantes envían al mismo tiempo). Plan gratis cubre miles de respuestas sin problema. Los archivos HTML deben servirse desde una URL pública (GitHub Pages) porque al abrirlos directamente desde el disco (file://...) el navegador bloquea las llamadas a APIs externas.
